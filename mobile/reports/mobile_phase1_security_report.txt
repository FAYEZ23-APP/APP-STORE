1. AUTHENTICATION STORAGE AUDIT FINDINGS:
--------------------------------------------------------------------------------
- Legacy Storage Audit:
  * AsyncStorage previously held non-credential data (deviceId, lastUserId, biometrics preferences, push tokens) alongside legacy token attempts.
  * No Redux or Redux-Persist exists in the project (React Context architecture).
  * No file-system cache or plain-text token dumps were found.
- Eliminated all possible persistence of JWT access tokens and refresh tokens in AsyncStorage.
- Centralized all token read, write, rotate, and clear operations into `src/services/authStorageService.js`.

2. SECURESTORE MIGRATION & TOKEN POLICY:
--------------------------------------------------------------------------------
- Access Token (`jwt_token`):
  * Primary storage: In-memory cache for ultra-fast, prompt-free API interceptor requests.
  * Persistence: Expo SecureStore exclusively. Never saved to AsyncStorage.
- Refresh Token (`refresh_token_${userId}`):
  * Persistence: Expo SecureStore exclusively.
  * User ID segment is strictly sanitized via `validateUserId()`: rejecting email addresses, path traversals (`/`, `\`), spaces, and SQL/script characters to prevent PII leakage in key names.
- Centralized Service API (`authStorageService.js`):
  * `saveTokens({ accessToken, refreshToken, userId, isBiometricBound })`
  * `getAccessToken()`
  * `getRefreshToken(userId)`
  * `updateAccessToken(accessToken)`
  * `rotateRefreshToken(userId, newRefreshToken)`
  * `clearAuthTokens(userId)`
  * `invalidateSession(userId)`
- Safe Legacy Migration (`migrateLegacyStorage()`):
  * Reads legacy credentials from AsyncStorage only when present.
  * Discards expired or corrupted JWTs.
  * Persists valid credentials to SecureStore and verifies by readback.
  * Removes legacy entries from AsyncStorage with zero leftover credentials.
  * Fails closed upon SecureStore failure to avoid corrupted/duplicate state.

3. HARDWARE-BACKED BIOMETRIC PROTECTION:
--------------------------------------------------------------------------------
- Companion Hardware-Bound Key (`bio_bound_token_${userId}`):
  * Stored via `SecureStore.setItemAsync` with `requireAuthentication: true` and `WHEN_UNLOCKED_THIS_DEVICE_ONLY`.
  * Detects Android Keystore `KeyPermanentlyInvalidatedException` and iOS Keychain `errSecAuthFailed` / `-25293`.
- Invalidation Handling:
  * When biometric credentials on the device change (fingerprint added or removed at OS level), the hardware key invalidates.
  * Handled via `handleBiometricInvalidationAlert`: clears remaining tokens, invalidates session, forces normal password login, and notifies user with bilingual Arabic and English alert.
- Performance:
  * API requests via `client.js` never trigger native biometric prompts; they use the in-memory access token.
  * Handled user cancellation (`user_cancel`), biometric lockout (`lockout`), unsupported hardware, and errors gracefully without crashing.

4. APPNAVIGATOR LOCK ENFORCEMENT & DEEP-LINK GATING:
--------------------------------------------------------------------------------
- Strict Navigation Gate:
  * `isLoading`: Renders an activity loading indicator. `NavigationContainer` is NOT mounted.
  * `isLocked`: Renders ONLY `UnlockScreen`. Authenticated navigation tree is completely unmounted and inaccessible.
- Deep Link & Notification Gating (`deepLinkValidator.js`):
  * External URLs (`marketplace://`, `https://marketplace.com`) arriving while locked/loading are intercepted at the root level.
  * Route parameters are sanitized against script injections, path traversals, and query manipulations.
  * Requests are queued in `pendingNavigation`.
  * Upon successful unlock, current authentication status and user role are strictly verified against the requested screen before navigating.
  * Queue is wiped immediately if user logs out or opts for "Use Password".
