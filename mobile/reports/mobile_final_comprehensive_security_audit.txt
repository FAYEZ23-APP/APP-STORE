2. SECURESTORE IMPLEMENTATION REPORT (MOB-006)
--------------------------------------------------------------------------------
- Centralized Service: mobile/src/services/authStorageService.js
- Storage Engine: expo-secure-store (Android Keystore / iOS Keychain).
- Key Policy:
  * Access token: jwt_token in SecureStore (and in-memory for non-blocking API calls).
  * Refresh token: refresh_token_${userId} in SecureStore exclusively.
  * Biometric companion: bio_token_${userId} in SecureStore.
- User ID Validation: sanitizeUserId() strips directory traversal, emails, and symbols.
- Migration Protocol (migrateLegacyStorage):
  * Scans AsyncStorage for legacy keys (jwt_token, token, accessToken, refresh_token).
  * Validates JWT structure and expiration (never migrates expired/corrupted tokens).
  * Migrates valid tokens to SecureStore, verifies write, then purges legacy keys.
  * Fail-closed policy: if migration fails, purges legacy keys and forces re-login.
- Audit: Verified zero tokens written to AsyncStorage across 100% of operations.

3. BIOMETRIC PROTECTION TEST REPORT (MOB-006)
--------------------------------------------------------------------------------
- Architecture: UI-level biometric unlock gate (UnlockScreen.js) backed by
  expo-local-authentication and hardware-backed biometric verification.
- Timeout & Inactivity Gate: DEFAULT_LOCK_TIMEOUT_MS = 2 minutes. App backgrounding
  timestamps are tracked in AppState listener; cold start immediately enters locked state
  if biometrics are enabled and refresh token exists.
- ZERO Pre-Unlock Network Requests: The application NEVER invokes /auth/refresh
  prior to successful biometric authentication.
- Key Invalidation Detection:
  * Android: KeyPermanentlyInvalidatedException caught when device fingerprints change.
  * iOS: errSecAuthFailed caught when biometric enrollment is altered.
  * Action: Prompts user that biometrics were invalidated and forces password unlock.

6. TOKEN LIFECYCLE & LOGOUT REPORT (MOB-005, MOB-010)
--------------------------------------------------------------------------------
- Single-Flight Refresh (performSingleFlightRefresh):
  * Concurrent 401 requests await a shared refresh promise.
  * Exactly 1 refresh request sent to /auth/refresh.
  * Session Epoch Guard: increments currentSessionEpoch on logout/switch; in-flight
    refresh responses are discarded and prevent session resurrection.
- Centralized Logout (logout, logoutAll):
  * Dispatches server revocation to /auth/logout with active refresh and push token.
  * Unregisters device push token via /notifications/unregister-token.
  * Purges SecureStore credentials and user-specific cart (@marketplace_cart_user_${id}).
  * Strictly preserves guest cart under @marketplace_cart_guest.
- ErrorBoundary Zero-PII Sanitization (errorSanitizer.js):
  * Redacts JWT tokens, authorization headers, emails, phone numbers, and filesystem paths.
  * In production (!__DEV__), renders only localized friendly message; zero stack trace output.

7. 2FA INTEGRATION REPORT (MOB-005)
--------------------------------------------------------------------------------
- Backend Endpoint: POST /api/auth/2fa/verify-login
- Challenge Ticket Handling:
  * TwoFactorToken is maintained strictly in React memory state.
  * Never written to persistent storage, navigation route parameters, or deep links.
  * User role and userId remain null throughout challenge.
- 6-Digit TOTP Input: OtpInput component with clipboard auto-fill and backspace support.
- First-Time Setup Activation: Displays manual entry key (secret) and forwards it to API.
- Expired Challenge Handling: Automatically clears challenge state and returns user to login.
