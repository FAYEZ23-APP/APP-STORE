1. OBJECTIVES IMPLEMENTED & VERIFIED
--------------------------------------------------------------------------------
- Single-Flight Token Refresh (performSingleFlightRefresh, resetClientSession):
  * Only one refresh operation executes at any given time.
  * Concurrent 401 requests share the identical single-flight refresh Promise.
  * Exactly 1 refresh request is dispatched to the backend /auth/refresh endpoint.
  * Rotated access and refresh tokens are persisted in SecureStore before resolution.
  * Session Epoch Guard (currentSessionEpoch): If user logs out or switches accounts
    while a network refresh request is in flight, the epoch guard intercepts the
    response, invalidates the save operation, and prevents resurrection of the old session.
- Centralized Secure Logout (AuthContext.logout / logoutAll / unlockWithPassword):
  * Calls resetClientSession() immediately to cancel pending in-flight refresh saves.
  * Server session revocation: dispatches /auth/logout with active refresh token and push token.
  * Push token lifecycle: unregisters push token from backend before local storage wipe.
  * SecureStore credentials purge: deletes jwt_token, refresh_token_${userId}, bio_token_${userId}.
  * In-memory authentication state reset: userRole=null, userId=null, isLocked=false.
  * Private cache cleanup: user-specific cart (@marketplace_cart_user_${userId}) wiped;
    Wishlist in-memory set reset to empty.
  * Guest cart preservation: guest shopping cart stored under @marketplace_cart_guest
    is strictly preserved across login, logout, and account switches.
- Push Notification Lifecycle & Account Isolation (notifications.js):
  * Associates active device push token with current userId via marketplace_device_push_user_id.
  * Account switching detection: when a different user logs in on a shared device,
    previous push token registration is revoked from the server before new binding.
  * Unregister on logout: /notifications/unregister-token invoked with active push token;
    marketplace_device_push_token_v1 and marketplace_device_push_user_id purged.
- Production ErrorBoundary Protection (ErrorBoundary.js & errorSanitizer.js):
  * Production mode (!__DEV__): never renders component stack, exception message, or paths.
    Displays localized friendly UI with retry action.
  * Zero-PII sanitization (sanitizeErrorDetails): redacts JWT tokens, authorization headers,
    email addresses, phone numbers, and local filesystem paths (Windows/Unix).
  * Development mode (__DEV__): preserves detailed error string and componentStack for debugging.
