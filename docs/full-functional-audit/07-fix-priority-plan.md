### ثانياً: الإصلاحات ذات الأولوية المتوسطة (Medium Priority Remediation)

#### 🛠️ FIX-MED-001: توحيد رمز الاستجابة عند حذف الفئات (`BUG-MED-001`)
- **الهدف:** توحيد استجابة عمليات الحذف الناجحة في المنصة لتعيد `204 NoContent` القياسي بدلاً من `200 OK` مع نص JSON.
- **الملفات المستهدفة:**
  - `Marketplace.API/Controllers/CategoriesController.cs`
  - `admin-web/src/api/categoriesApi.js`
- **خطوات التنفيذ:**
  1. تعديل دالة `DeleteCategory` في `CategoriesController.cs`:
     ```csharp
     // استبدال:
     return Ok(new { success = true, message = "تم حذف الفئة بنجاح." });
     // بـ:
     return NoContent();
     ```
  2. تعديل سمة التوثيق `[ProducesResponseType(StatusCodes.Status204NoContent)]`.
  3. التأكد من معالجة الواجهة في `CategoriesPage.jsx` للاستجابة `204` بدون انتظار بيانات في `response.data`.
- **خطة التحقق والتراجع:** تشغيل `dotnet test` والتحقق من عدم تأثر شاشة إدارة الأقسام.

---

#### 🛠️ FIX-MED-002: إضافة بطاقة مخصصة للمتجر المغلق أو قيد المراجعة (`BUG-MED-002`)
- **الهدف:** استبدال رسالة الخطأ الشبكي العامة في صفحة المتجر ببطاقة توضيحية راقية توضح أن التاجر معطل أو متوقّف مؤقتاً.
- **الملفات المستهدفة:**
  - `admin-web/src/pages/SellerStorePage.jsx`
  - `mobile/src/screens/buyer/SellerStoreScreen.js`
- **خطوات التنفيذ:**
  1. فحص رمز الخطأ في استدعاء `getSellerStorefront`؛ إذا كان `err.response?.status === 404`:
     - عرض بطاقة معززة برمز المتجر المغلق (Store Closed Icon).
     - نص واضح باللغتين: "هذا المتجر غير متاح حالياً أو يخضع لمراجعة الإدارة".
     - زر تفاعلي: "العودة لتصفح المنتجات" ينقل لصفحة الكتالوج.
- **خطة التحقق:** حظر تاجر تجريبي ومحاولة الدخول على رابطه والتأكد من ظهور البطاقة الأنيقة.
